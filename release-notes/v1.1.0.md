# Envoy AI Gateway v1.1.0

> Plain-markdown copy of the v1.1.0 release notes, suitable for pasting into the GitHub release body. The full rendered version lives at https://aigateway.envoyproxy.io/release-notes/v1.1.

Envoy AI Gateway v1.1.0 is the first minor release on the stable 1.x API. Count tokens before you spend them: a vLLM-compatible `/tokenize` endpoint covers OpenAI-compatible, Bedrock, Vertex AI Gemini, and Anthropic-on-cloud backends, alongside native Anthropic `/anthropic/v1/messages/count_tokens` and OpenAI `/v1/responses/input_tokens`. Multi-tenant platforms can inject per-request upstream credentials from a trusted filter instead of sharing one static key. Streaming calls that stall on time-to-first-token now fail over to the next backend via `streamIdleTimeout`. MCP routes pick up hostname scoping and CEL-based backend selection so a shared MCP gateway can isolate tenants. Observability grows with optional OpenTelemetry GenAI semantic conventions, an importable Grafana dashboard, and JSON logs. Locked-down networks can send all upstream AI traffic through an HTTP CONNECT forward proxy.

## ⚠️ Breaking Changes

- **Helm controller security context defaults** — The Helm chart now sets a restricted `podSecurityContext` and container `securityContext` on the controller (non-root UID/GID 65532, all capabilities dropped, no privilege escalation, RuntimeDefault seccomp). Previously both were empty. If you run a custom controller image that cannot use UID 65532, override `controller.podSecurityContext` and `controller.securityContext` in your values. `PodDisruptionBudget` remains off unless you set `controller.podDisruptionBudget.enabled: true`.

## ✨ New Features

### Token Counting APIs

- **vLLM-compatible `/tokenize` across providers** — Count tokens for a prompt without generating a completion. Chat messages and completion prompts are accepted in the [vLLM tokenize](https://docs.vllm.ai/en/latest/api/tokenization.html) request shape, so cost estimation and context-window checks work the same way against vLLM, GCP Vertex AI Gemini, GCP Anthropic, AWS Bedrock Converse, and AWS Anthropic. Translated backends return `{"count": N}`; native vLLM backends may also return token IDs and `max_model_len`. OpenAI itself has no tokenize REST API — configure an OpenAI-schema backend only when the upstream (for example vLLM) actually implements `/tokenize`.
- **Anthropic `/anthropic/v1/messages/count_tokens`** — Anthropic-native clients can count input tokens for a Messages request — including system prompts and tools — without creating a message. Routed to Anthropic, GCP Anthropic, and AWS Anthropic backends.
- **OpenAI `/v1/responses/input_tokens`** — Send the same body as `/v1/responses` and get back an input token count. Works with OpenAI and Azure OpenAI (with automatic `api-version` injection).
- **Anthropic-format `/anthropic/v1/models`** — Claude clients that call Anthropic's model list endpoint now get the gateway's configured catalog in Anthropic's response shape, scoped by hostname the same way `/v1/models` is.

### Per-Request Credentials & Egress

- **Per-request upstream credentials via `credentialOverride`** — A trusted filter (ext_authz or a preceding ext_proc) can supply the backend credential per request instead of every caller sharing one static key in `BackendSecurityPolicy`. Source the credential from Envoy dynamic metadata (preferred — clients cannot forge it) or from a request header that the gateway strips before the backend sees it. Missing credentials fall back to the configured secret by default, or return 401 when `fallbackToConfigured` is `false`. API keys, Anthropic, Azure, GCP, and AWS SigV4 are all supported.
- **Per-request AWS SigV4 credentials** — AWSCredentials overrides carry the three-part SigV4 input — access key, secret, and optional session token. Header source uses the `x-aigw-aws-` prefix (or a custom prefix such as `x-aws-`); metadata source reads a struct with fixed `accessKeyId` / `secretAccessKey` / `sessionToken` fields. A partial credential fails the request instead of silently falling back. Prefer metadata over headers: a secret access key on the wire is a worse leak than an API key.
- **HTTP CONNECT forward proxy for upstream AI traffic** — `GatewayConfig.spec.forwardProxy` tunnels every upstream LLM connection from Gateways that reference the config through an HTTP CONNECT proxy. The address is `host:port` (hostname or IP; port required). Envoy's `http_11_proxy` transport socket preserves the upstream TLS session.
- **Correct SigV4 signing for Bedrock VPC endpoints** — Bedrock requests through PrivateLink or a custom internal hostname now sign over the actual upstream host resolved at config time, not the downstream gateway authority. Region is derived from the Bedrock host when it encodes one, so a VPCE in a different region than the configured `BackendSecurityPolicy` still produces a valid signature instead of a silent 403.

### Streaming Resilience

- **Stream idle timeout with failover to the next backend** — `AIGatewayRouteRule.streamIdleTimeout` bounds how long Envoy waits without receiving any upstream bytes on a streaming response. If the timer fires before the first token, Envoy resets the stream and a retry policy can fail over to the next backend in the rule. If it fires mid-stream after bytes have already reached the client, the stream is cut with a 504. Pair it with a `BackendTrafficPolicy` whose retry covers reset; without retry, the idle timeout still fails fast but does not fail over.

### MCP Gateway

- **Hostname-based routing on `MCPRoute`** — `MCPRoute.spec.hostnames` scopes an MCP endpoint to specific hosts, the same way `AIGatewayRoute.spec.hostnames` scopes LLM traffic. Tenants on `team-a.mcp.example.com` and `team-b.mcp.example.com` can expose different MCP server sets from a single Gateway.
- **Per-request MCP backend selection** — `MCPRoute.spec.backendSelector` restricts which of a route's backends a given client session fans out to. CEL rules are evaluated once per candidate backend at session initialize — not on every `tools/call`. Default action is Deny; if no backend is allowed, initialize returns 403 rather than a 500.
- **Merged backend capabilities and shared Backends** — Initialize now advertises capability extensions declared by the backends themselves. The controller also shares one Envoy Gateway `Backend` per namespace instead of creating one per `MCPRoute`.

### Observability

- **OpenTelemetry GenAI semantic conventions** — Set `AI_GATEWAY_TRACING_SEMCONV=gen_ai` on the ext-proc to emit `gen_ai.*` span attributes instead of OpenInference. Message content is opt-in via `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT`. The same flag switches MCP spans to the OpenTelemetry MCP conventions. An unrecognized value fails startup rather than silently falling back. Span names include the model, so cardinality is higher than OpenInference's fixed names. The GenAI conventions are still marked Development upstream.
- **Importable Grafana dashboard for GenAI metrics** — An example dashboard covering the `gen_ai_*` Prometheus metrics ships in `examples/monitoring/grafana-dashboard.json`, including token usage by type, request duration percentiles, time-to-first-token vs inter-token latency, original-vs-response model mismatch, QPS, token burn rate, and per-model success rate.
- **MCP resource URI in access logs and JSON controller logs** — Resource reads now populate `mcp_resource_uri` in the `io.envoy.ai_gateway` dynamic metadata. Controller and ext-proc logs accept `--logFormat=json` (Helm: `controller.logFormat` / `extProc.logFormat`). MCP requests also honour inbound W3C `traceparent`.

### Provider Translation & API Compatibility

- **Structured output for Claude on GCP Vertex AI** — JSON-schema constrained decoding now works for Claude models on Vertex AI that advertise `output_config` (including Claude 4.5, Opus 4.6+, Sonnet 5, and Mythos/Fable). This closes the gap left in v0.6, when Anthropic and AWS Bedrock Claude already supported structured output but GCP did not. Unsupported models skip the constraint rather than failing the request.
- **OpenAI `reasoning_effort` forwarded to Bedrock as `reasoning_config`** — Clients that set `reasoning_effort` on chat completions now have that value forwarded to AWS Bedrock as `additionalModelRequestFields.reasoning_config`, so Nova and GLM models pick up the same effort the OpenAI client already sends.
- **Responses API `tool_search`, unknown tools, and Codex inputs** — The Responses API accepts the built-in `tool_search` tool and `additional_tools`, preserves unknown tool types instead of rejecting the request, and accepts Codex-style agent input items.

### Helm & Operations

- **Controller PDB, topology spread, pod labels, and security context** — The Helm chart can emit a `PodDisruptionBudget` (`controller.podDisruptionBudget.enabled`, default off), honour `topologySpreadConstraints`, and attach extra `podLabels`. Controller pods now default to a restricted security context (non-root UID 65532, all capabilities dropped, no privilege escalation).
- **Sharded ext-proc config secrets** — Filter configuration is split across multiple Secrets instead of a single object, so large Gateway configs no longer fail Kubernetes' 1 MiB Secret size limit. The `aigw` CLI reassembles the bundle automatically. Ext-proc pods are also rolled when injected config drifts.

## 🔗 API Updates

- **`AIGatewayRouteRule.name`** — Optional unique name copied onto the generated `HTTPRoute` rule. Names must be unique within the route; `route-not-found` is reserved.
- **`AIGatewayRouteRule.streamIdleTimeout`** — Optional Gateway API duration. The extension server sets `route.retry_policy.per_try_idle_timeout` on every xDS route generated from the rule. Unset means no per-try idle timeout.
- **`BackendSecurityPolicy.spec.credentialOverride` (v1beta1)** — Optional per-request credential source. Exactly one of `fromRequestHeaders` or `fromDynamicMetadata` must be set. Header defaults are `x-aigw-api-key`, `x-aigw-anthropic-api-key`, `x-aigw-azure-api-key`, `x-aigw-azure-access-token`, `x-aigw-gcp-access-token`, and the `x-aigw-aws-` prefix for SigV4. Metadata requires `namespace`; `key` defaults to the matching `x-aigw-*` name (or `x-aigw-aws-credentials` for AWS). `fallbackToConfigured` defaults to `true`.
- **`GatewayConfig.spec.forwardProxy`** — Optional HTTP CONNECT proxy for all upstream AI traffic from Gateways that reference this config. `address` is required and must be `host:port`.
- **`MCPRoute.spec.hostnames`** — Optional list of hostnames (max 16) matched against the HTTP Host header.
- **`MCPRoute.spec.backendSelector`** — Optional CEL-based selector evaluated once per candidate backend at session initialize. `defaultAction` defaults to Deny. Each rule has an optional `cel` expression (max 4096 characters) and `action` (default Allow). Max 32 rules. `request.mcp.method`, `request.mcp.tool`, and `request.mcp.params` are not populated at selection time.

## 📖 Upgrade Guidance

Upgrading from **v1.0** requires no CRD migrations. New fields are optional and backward compatible. Review the Helm security-context change above if you override the controller image.

### Helm security context

If the official controller image works for you, no action is needed. To restore empty security contexts (for example a custom image that cannot run as UID 65532):

```yaml
controller:
  podSecurityContext: {}
  securityContext: {}
```

JSON logs: set `controller.logFormat` and `extProc.logFormat` to `json`. Enable a PDB with `controller.podDisruptionBudget.enabled: true` when you run more than one replica.
